## 一、项目背景与痛点

### 1.1 背景:湘西有好物,小店有难处

湘西地处武陵山区腹地,独特的气候与生态孕育了腊肉、猕猴桃、黄金茶、莓茶、姜糖等一批品质出众的土特产。近年来,随着直播与电商进村,越来越多的土特产小店尝试线上销售,把"山里的好东西"卖向全国。

然而,湘西特产电商的经营者大多是**个体小店、家庭作坊、合作社**:一人身兼采购、加工、上架、发货、客服数职。线上生意与线下不同——顾客看不见实物,下单前必然要问:**"这腊肉怎么保存?""黄金茶是明前还是明后?""猕猴桃发到北方会不会坏?"** 一问一答之间,信任才建立,订单才成交。

### 1.2 痛点:小店请不起客服,问得慢就是丢单

对湘西特产小店而言,客服这件事有三个绕不过去的难处:

1. **成本难**:为小店请一名专职客服,每月数千元人力成本,大多数小店承担不起;店主自己回复,则经常"边打包边回消息",回复慢、漏回多。
2. **专业难**:特产咨询有门槛——储存方法、食用方式、产地季节、物流保鲜,答得不专业,顾客转头就走。
3. **持续难**:顾客提问不分时段,凌晨的咨询往往要到第二天才被看到,订单早已流失。

**核心矛盾**:小店需要"随时在线、懂得自家商品、几乎不花钱"的客服,而市面上没有这样的产品。

### 1.3 我们的答案:让 AI 做小店的"乡音客服"

本项目的答案是:用检索增强生成(RAG)技术,让每个特产小店零成本拥有自己的 AI 客服——**店主把自家特产资料上传,AI 只依据这些真实资料回答顾客,每个答案还标注出处,绝不瞎编**。这就是"乡音智答":用 AI 听懂家乡的好物,替小店答好每一位远方的顾客。

## 二、产品与技术方案

### 2.1 产品形态:一端上传,一端提问

**店主端(资料上传)**:店主把自家特产的产品说明、储存方法、食用指南、常见问题等资料(支持 PDF、Word、Excel 等 6 种格式)上传到系统,即完成"训练"——无需任何技术基础,全程网页操作。

**顾客端(扫码提问)**:顾客扫描小店提供的二维码,像发微信一样用大白话提问("这个腊肉放冰箱能放多久?"),AI 基于店主上传的真实资料即时作答,并展示回答所依据的原文片段。

### 2.2 现有基础:通用电商 RAG 原型(已完成并开源)

项目已完成通用电商领域的 RAG 智能问答原型,核心能力如下:

| 能力 | 说明 | 验证数据 |
|---|---|---|
| 知识入库 | 6 种格式文档解析、中文分块、云端向量化 | 10 类 39 份演示文档全部入库 |
| 混合检索 | 向量 + 关键词(BM25)双路召回,RRF 融合 | 单次检索约 0.16 秒 |
| 防幻觉 | 只依据检索资料作答,答案标注 [n] 引用;模型漏标时自动溯源兜底 | 知识库没有的内容明确回答"没有找到" |
| 多用户体系 | 注册登录、多会话、历史找回、权限隔离 | — |
| 性能 | 自研压测工具实测 100 人并发 | 成功率 99%,平均响应 3.47 秒 |
| 质量 | 60 项单元测试 | 全部通过 |

代码已在 **GitHub、Gitee 双平台开源**(github.com/blfkz/DM----RAG;gitee.com/blfkz/langchain-rag),技术方案公开透明。

### 2.3 开发方式(如实说明)

我作为项目第一完成人,主导完成了**需求设计、RAG 架构设计与技术选型**(如为什么采用混合检索、为什么选择云端大模型 API 而非本地部署、防幻觉的三层机制设计等关键决策),开发过程中使用 AI 工具辅助代码实现与调试。

### 2.4 下一阶段开发计划:从"通用电商"到"湘西特产"

在通用原型基础上,下一阶段改造方向:

1. **湘西特产知识库模板**:针对腊肉、黄金茶、猕猴桃、莓茶等特产品类,设计标准化的资料模板(产品介绍/储存/食用/物流/售后),让店主"照着填"即可完成知识库搭建;
2. **店主端界面改造**:面向零技术基础的小店店主,极简化上传与维护流程;
3. **顾客端轻量化**:扫码即问,适配手机浏览器,降低顾客使用门槛。

## 三、市场分析

### 3.1 中小电商商家的客服痛点(通用市场)

中小电商商家普遍缺乏专职客服能力:咨询高峰顾此失彼、深夜咨询无人应答、重复问题反复消耗人力。市面上的智能客服产品(如电商平台自带机器人、大型 SaaS 客服系统)存在两个明显问题:**一是贵**——成熟 SaaS 按坐席收费,小商家用不起;**二是"不懂货"**——通用客服机器人靠预设问答库,答不出"这家的腊肉到底怎么熏的"这类具体问题。而 RAG 技术的特点恰恰是"基于商家自己的资料回答",完美契合这一缺口。

### 3.2 湘西土特产电商的需求(目标市场)

湘西土特产电商具有三个适合本项目切入的特点:

1. **产品有故事、有讲究**:土特产的储存、食用、产地、季节知识丰富,顾客咨询频率高、内容专业——正是 RAG 知识库擅长的场景;
2. **商家分散且规模小**:大量小店、合作社、农户网店分散在县域乡镇,无力负担专业客服;
3. **信任是成交关键**:土特产顾客对"产地正宗、食用安全"极为在意,AI 答案附引用原文,反而比人工回复更显专业可信。

目标用户:湘西州及周边县域的土特产小店、合作社、农户网店,以及文旅场景(游客扫码了解特产)。

### 3.3 竞争分析

| 竞品类型 | 代表 | 不足 |
|---|---|---|
| 通用智能客服 SaaS | 大型客服云平台 | 按坐席收费,小店用不起;预设问答库,不懂具体商品 |
| 人工客服外包 | 客服外包公司 | 月费数千元,小店难以承受 |
| 电商平台内置机器人 | 各平台自带 | 只能答平台模板问题,无法基于商家资料 |

**本项目的差异化**:①轻量——网页即用,零技术门槛;②本地化——专为土特产小店设计;③可信——答案带引用、不瞎编,这恰是通用客服机器人做不到的。

## 四、商业模式(创意阶段设想)

> 如实说明:本项目处于创意计划阶段,**目前无任何收入、无付费客户、无公司实体**。以下为未来设想。

1. **公益起步**:试点期对签约小店**免费开放**,换取真实使用数据与案例(红旅赛道"真实落地"的核心);
2. **小额订阅**:试点成熟后,向商家收取低年费(参照小店可承受范围定价,目标低于人工客服成本的 1/10);
3. **延伸服务**:特产带货咨询、文旅导览问答等场景合作;
4. **政企合作**:申报乡村振兴相关项目,争取县域商务部门、供销社的资源支持。

## 七、风险分析与应对方案

| 风险 | 分析 | 应对方案 |
|---|---|---|
| 云端 API 成本与依赖 | AI 能力依赖云端大模型服务,存在按量费用 | 已采用轻量架构:云端只承担问答与向量化,本地零负担;试点阶段咨询量有限,费用可控(实测压测 600 问折算约 2 元);后续可批量采购或申请云厂商教育/助农额度 |
| 商家接受度 | 小店店主技术基础薄弱,可能对新工具存疑 | 上门演示+免费试用;店主端界面做到"传文件就会用";用商家自己的特产资料当场演示问答效果 |
| 竞争风险 | 大厂智能客服产品下沉 | 坚持差异化:本地化特产知识模板、防幻觉+引用可信、开源透明;大厂产品按坐席收费的模式天然排斥小微商家 |
| 团队人力 | 目前单人开发,试点运营精力有限 | 按计划招募队友分工;争取学校与指导老师支持;技术主体已完成,后续迭代工作量可控 |
| 回答准确性 | 知识库资料不全时可能答不上 | 系统已有"知识库没有就明确说没有"的防幻觉机制,宁可说不懂,绝不瞎编;持续扩充知识库 |
