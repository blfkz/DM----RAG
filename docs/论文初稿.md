# 基于 RAG 大模型的湘西土特产智能助农问答系统设计与实现

邓铭

(吉首大学 计算机科学与工程学院,湖南 吉首 416000)

**摘要**:针对湘西土特产小店客服成本高、商品知识零散、通用大模型回答存在幻觉且不可溯源等问题,设计并实现了一套基于检索增强生成(RAG)技术的智能助农问答系统。系统采用"店主上传资料、顾客扫码提问"的双端形态,店主将特产说明、保存方式等资料上传后,系统经解析、分块、向量化存入向量数据库;顾客提问时,系统通过向量与关键词双路混合检索召回知识片段,结合防幻觉提示词约束与引用溯源机制生成回答。实验表明:在 42 个测试问题上,系统对知识库外问题 100% 诚实拒答,回答全部附带可溯源的引用标注,平均响应时间 1.8 秒;100 人并发压测成功率达 99%。系统已开源,为湘西土特产助农提供了轻量化、可落地的技术方案。

**关键词**:检索增强生成;智能问答;大模型;向量数据库;助农

**Abstract**: To address the problems of high customer-service cost, scattered product knowledge and hallucination in generic large language models for small specialty stores in Xiangxi, an intelligent Q&A system based on Retrieval-Augmented Generation (RAG) is designed and implemented. The system adopts a two-end form: store owners upload specialty documents, and customers ask questions by scanning a QR code. Documents are parsed, chunked and embedded into a vector database; questions are answered through hybrid retrieval combining vector and keyword search, with anti-hallucination prompt constraints and citation tracing. Experiments on 42 test questions show that the system honestly refuses all out-of-knowledge questions, all answers carry traceable citations, and the average response time is 1.8 seconds; a 100-user concurrent stress test achieves 99% success rate. The system is open-sourced, providing a lightweight and practical solution for rural e-commerce.

**Key words**: retrieval-augmented generation; intelligent question answering; large language model; vector database; rural e-commerce

## 1 引言

乡村振兴战略背景下,农村电商快速发展,湘西土家族苗族自治州的腊肉、黄金茶、猕猴桃等土特产借助电商渠道走向全国。然而,特产电商的经营者多为个体小店与家庭作坊,店主一人身兼采购、销售、发货、客服数职。线上顾客看不见实物,下单前必然咨询商品的保存方法、食用方式、产地信息等问题,咨询高峰与深夜时段往往无人应答,大量订单因回复不及时而流失。

现有解决方案存在明显不足:人工客服成本高,小店难以承受;成熟客服 SaaS 按坐席收费,面向中大型企业;电商平台内置机器人依赖预设问答库,无法基于商家自己的资料作答。小店真正需要的,是一个"随时在线、懂得自家商品、几乎不花钱"的客服。

近年来,大语言模型(LLM)展现出强大的语言理解与生成能力,但其训练数据与商家的商品资料相互独立,直接用于客服场景会产生"幻觉"——模型可能一本正经地编造商品信息,且回答无法溯源。检索增强生成(RAG)技术为此提供了有效路径:先根据问题检索商家资料库中的相关片段,再让大模型仅依据检索片段生成回答,从而把模型的"知识边界"收敛到商家自己的资料范围内。

基于上述背景,本文设计并实现了一套面向湘西土特产小店的 RAG 智能问答系统,完成特产知识库建设、混合检索、防幻觉机制与引用溯源等核心模块,并通过对比实验与并发压测验证了系统的实用性与稳定性。

## 2 技术概述

### 2.1 大语言模型与云端 API 调用

系统选用通义千问 qwen-plus 作为生成模型,通过阿里云百炼平台的 OpenAI 兼容接口以云端 API 方式调用。选择云端调用而非本地部署的原因在于:本地部署大模型对硬件要求高,小店场景难以负担;云端 API 按量计费、即用即付,与本系统"轻量化、低门槛"的定位一致。向量化采用 text-embedding-v4 模型,输出 1024 维向量,同样通过云端 API 调用。

### 2.2 检索增强生成(RAG)

RAG 由 Lewis 等人于 2020 年提出,核心思想是在生成之前先检索外部知识库,将检索到的文本与问题一同输入大模型,使回答有据可依。RAG 已成为大模型落地垂直领域的主流方案,国内学者对其方法与应用开展了系统梳理[4-5]。对土特产小店而言,RAG 的价值在于:AI 只依据店主上传的资料回答,店主可以完全控制客服的"知识范围"。

### 2.3 向量数据库与混合检索

文本经 Embedding 模型映射为高维向量后存入向量数据库,检索时通过余弦相似度召回语义相近的片段。本系统使用开源的 Chroma 向量数据库,本地持久化存储。纯向量检索对"黄金茶""0~4℃"等精确词存在字面匹配不足的问题,因此系统引入 BM25 关键词检索作为补充,两路召回结果通过 RRF(Reciprocal Rank Fusion)算法融合排序,兼顾语义相近与字面精确两种命中方式。

## 3 系统总体设计

### 3.1 系统架构

系统采用分层架构,自下而上分为三层:数据层包括 SQLite 业务数据库(账号、会话、消息、知识库元信息)与 Chroma 向量数据库(知识片段及其向量);核心逻辑层以 LangChain 为编排框架,包含文档解析、中文分块、云端向量化、混合检索、提示词组装、引用解析等模块;应用层基于 Streamlit 提供网页界面,包含登录、问答、知识库管理、统计面板四个页面。大模型与向量化能力全部通过云端 API 提供,本地仅承担轻量业务逻辑,对部署环境要求极低。

### 3.2 湘西特产知识库设计

系统面向湘西土特产构建了演示知识库,共收录 23 份特产文档,覆盖茶叶(保靖黄金茶、古丈毛尖、永顺莓茶)、肉制品(湘西腊肉、血粑鸭)、水果(十八洞村猕猴桃、泸溪椪柑)、传统食品(凤凰姜糖、湘西糍粑、湘西米酒)、农产品(龙山百合、土蜂蜜、葛根粉、茶油)与手工艺品(苗绣团扇、竹编)六大类,文件格式涵盖 PDF、Word、Excel、CSV、TXT、Markdown 六种。每份文档按统一结构编写,包含产品介绍、产地特色、保存方式、选购指南与常见问题五个板块,保证切片后各片段语义完整、问答效果稳定。

### 3.3 双端产品形态

店主端:店主通过网页上传自家特产资料,系统自动完成解析、清洗、分块、向量化入库,全程无需技术基础;顾客端:顾客扫描小店二维码,像发微信一样用自然语言提问,系统即时返回带引用标注的回答。

## 4 模块实现

### 4.1 文档入库模块

入库流程为:解析、清洗、分块、向量化、写库五步。解析模块按扩展名分发,支持 PDF(逐页提取并记录页码)、Word(段落与表格)、Excel/CSV(每行渲染为"列名: 值"文本)、TXT/Markdown(多编码兼容,依次尝试 utf-8、utf-8-sig、gbk)。清洗模块去除空行、控制字符与常见乱码。分块采用递归字符分割器,分隔符显式加入中文标点,块长 500 字、重叠 80 字,避免商品参数被切碎。向量化采用云端批量接口(单次最多 10 段),写入 Chroma 时使用"文档号_块序号"确定性编号并支持幂等覆盖,保证重复上传不产生重复向量。

### 4.2 混合检索模块

检索分两路并行:向量路将问题编码后按余弦相似度召回 top20 片段;关键词路以 jieba 分词构建 BM25 索引,按字面相关性召回 top20 片段。两路结果经 RRF 融合取 top6 送入生成环节。BM25 索引带版本号缓存,文档变更时版本号自增触发重建,保证索引与知识库内容一致。

### 4.3 防幻觉与引用模块

系统以三层机制保证回答可信。第一层检索约束:模型只能看到检索出的真实片段;第二层提示词约束:系统提示词硬性要求"只依据资料作答,资料不足必须明确说明没有找到",并将检索片段显式预编号,让模型"抄编号"而非自行编号;第三层引用校验:从回答中解析编号引用并校验范围,若模型未标注任何引用,则按句切分回答、与检索片段计算向量相似度自动溯源,为回答挂接最相关的原文片段。三层机制共同保证任何回答都有据可查。

### 4.4 多用户与性能优化

系统实现注册登录、多会话管理、历史对话找回与权限隔离(管理员与普通用户)。性能方面:生成采用流式输出降低首字延迟;大文档入库在后台线程处理,页面即时返回;数据库启用 WAL 模式并建立常用索引;长会话超过 20 条消息时自动压缩摘要控制上下文体积;云端调用配置自动重试,网络抖动自愈。

## 5 实验测试

### 5.1 实验环境

实验在 Windows 11 环境下进行,生成模型为 qwen-plus,向量化模型为 text-embedding-v4,均通过云端 API 调用;向量数据库为 Chroma,业务数据库为 SQLite。

### 5.2 对比实验:普通大模型直答 vs RAG 系统

设计 42 个湘西特产相关问题,分为三类:知识库内可答问题 32 条(保存、食用、产地、选购等)、知识库外问题 7 条(如"湘西特产里有没有无人机""湘西特产可以治癌症吗")、边界问题 3 条。每条问题分别由普通大模型直接回答(无检索、无知识库)与本系统 RAG 链路回答,人工对照知识库内容评估。实验结果见表 1。

表 1 对比实验结果

| 指标 | 普通大模型直答 | RAG 系统 |
| --- | --- | --- |
| 平均响应时间 | 8.5 s | 1.8 s |
| 回答附带引用比例 | 0% | 100% |
| 知识库外问题诚实拒答率 | 0/7 | 7/7 |
| 知识库内问题准确率 | 93.8%(30/32) | 96.9%(31/32) |
| 口径可控性 | 不可控 | 完全由店主资料决定 |

分析:(1)知识库内问题上,两路准确率接近,但普通大模型出现张冠李戴——将保靖黄金茶产地错误表述为"安化",而 RAG 系统严格依据知识库作答;(2)知识库外问题上差异显著:普通大模型全部自由发挥,包括编造品牌、创作诗词等不可控行为,而 RAG 系统 7 条全部诚实回答"知识库中没有找到",防幻觉表现稳定;(3)RAG 回答全部附带引用标注,顾客可展开查看原文依据,信任度显著更高;(4)由于 RAG 回答聚焦于检索片段,平均响应时间反而优于自由发挥的直答模式。

### 5.3 并发性能测试

编写多线程压测工具模拟 100 名用户同时提问,每人每 20 秒提问一次,持续 2 分钟,共产生 600 次问答。结果为:成功 594 次,成功率 99.0%,平均响应 3.47 秒,吞吐 5.2 问/秒;6 次失败全部为云端 API 限流,本地检索与数据库零失败。结果表明系统在县域小店场景的并发需求下运行稳定。

### 5.4 单元测试

系统核心模块编写 60 项自动化单元测试,覆盖认证、分块、引用解析、检索融合、会话管理、文档解析、文件指纹七组模块,全部通过,保障了代码质量与后续迭代安全。

## 6 总结与展望

本文设计并实现了一套基于 RAG 的湘西土特产智能助农问答系统:完成六大类 23 份特产文档的知识库建设,实现混合检索、三层防幻觉与引用溯源机制,对比实验验证了系统在准确率、防幻觉、可溯源性与响应速度上的综合优势,100 人并发压测成功率达 99%。系统代码已在 GitHub、Gitee 开源。

下一步工作包括:对接湘西本地特产小店开展免费试点,积累真实使用数据;扩充特产知识库模板并优化店主端操作流程;结合咨询数据分析完善知识库内容,形成"用数据反哺知识库"的闭环。
